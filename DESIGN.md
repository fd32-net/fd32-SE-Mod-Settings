# Mod Settings — проект API

Черновик 2, 2026-11-19. Этап 2 (ядро) сделан в V0.4: `Client\ModSettings.cs` — флажок, число, пояснение (Label), разделитель, кнопка,
своё окно, «ОК»/отказ; остальное ниже — пока предложение.
Решения пользователя и факты из кода игры — в заметке `~/.claude/notes/se-mod-settings-hub.md`.

Мод делается для всех мододелов, поэтому главное требование к API — **простота и понятность**:
мод описывает настройки в несколько строк, отдаёт и забирает значения и ничего не знает
об окнах и протоколе.

**Граница ответственности.** Центр только **рисует окно** и сообщает моду, что выбрал игрок.
Значения **хранит сам мод** (центр ничего не сохраняет). Правильность значений **проверяет сам мод**:
на «ОК» он получает новые значения и может отказать с сообщением об ошибке.

---

## 1. Как это устроено

- **Центр** (`Mod Settings`, отдельный мод в Workshop) рисует кнопку-шестерёнку справа от «Настроек»
  в меню Esc, подменю со списком модов и окно настроек каждого мода. Окно и контролы — как ванильные.
- **Клиентский файл** `ModSettings.cs` — один файл, который мододел копирует в свой мод
  (`Data\Scripts\<Мод>\ModSettings.cs`). В нём всё API для мода. Каждый мод компилируется
  отдельно, поэтому одинаковые имена классов в разных модах друг другу не мешают.
- Центр указывается у мода как **обязательная зависимость Workshop** — игра скачивает его сама.
- Мод и центр общаются через `SendModMessage` / `RegisterMessageHandler` на своём канале.
  Мододел этого не видит.

---

## 2. Как мод описывает настройки (то, что видит мододел)

Стиль: настройка — это объект-«ручка». Мод создаёт его один раз, сохраняет в поле
и дальше просто читает `.Value`. Тонкая подстройка — цепочкой методов.

### 2.1 Пример: MagRail

```csharp
using ModSettings;
using Sandbox.ModAPI;
using VRage.Game.Components;
using VRage.Input;
using VRageMath;

[MySessionComponentDescriptor(MyUpdateOrder.AfterSimulation)]
public class MagRailSettings : MySessionComponentBase
{
    public static SettingsMenu Menu;
    public static HotkeySetting LinkKey, MultiKey;
    public static NumberSetting CruiseSpeed, HudScale;
    public static ToggleSetting ShowHints;
    public static ChoiceSetting SpeedUnits;
    public static ColorSetting RailColor;

    public override void LoadData()
    {
        // id — постоянный ключ мода (не менять между версиями), затем имя и версия для подменю
        Menu = new SettingsMenu("magrail", "MagRail Systems", "0.9.3");

        var linker = Menu.Tab("Linker");
        var keys = linker.Group("Клавиши");
        LinkKey  = keys.Hotkey("link",  "Связать",            MyKeys.R);
        MultiKey = keys.Hotkey("multi", "Выбор нескольких",   MyKeys.Control)
                       .Tooltip("Удерживать вместе с кликом");

        var train = Menu.Tab("Поезд");
        CruiseSpeed = train.Number("cruise", "Скорость круиза", 20)
                           .Range(0, 120).Step(5).Unit("м/с")
                           .Slider().Field().Buttons();          // все три элемента в одной строке
        SpeedUnits  = train.Choice("units", "Единицы скорости", "ms")
                           .Option("ms", "м/с").Option("kmh", "км/ч");

        var hud = train.Group("HUD").Collapsible();
        ShowHints = hud.Toggle("hints", "Подсказки на экране", true);
        HudScale  = hud.Number("hudscale", "Масштаб", 1).Range(0.5f, 2).Step(0.1f).Decimals(1);
        Menu.Editing += e => HudScale.Enabled = e.New(ShowHints);  // мод сам решает: серый, пока галочка снята
        RailColor = hud.Color("rail", "Цвет подсветки рельса", new Color(80, 160, 255));

        train.Separator();
        train.Button("Сбросить статистику поездов",
                     () => Menu.ShowConfirm("Сбросить статистику?", yes => { if (yes) ResetStats(); }));

        // свои сохранённые значения мод загружает сам (тут — свой класс мода MyConfig)
        MyConfig.Load();
        CruiseSpeed.Value = MyConfig.Cruise;
        LinkKey.Value     = MyConfig.LinkKey;
        // ...

        // проверка и сохранение — после «ОК» в окне
        Menu.Applying += OnApplying;
        Menu.Applied  += () => MyConfig.Save();

        Menu.Register();   // отдать описание центру
    }

    void OnApplying(SettingsApply e)
    {
        if (e.New(ShowHints) && e.New(HudScale) > 1.5f)
            e.Cancel("Подсказки при масштабе больше 1.5 не помещаются на экран", HudScale);
    }

    public override void UpdateAfterSimulation()
    {
        if (LinkKey.IsNewPressed())
            StartLink();
        float speed = CruiseSpeed.Value;
    }

    protected override void UnloadData()
    {
        Menu.Dispose();
    }
}
```

### 2.2 Структура

```
SettingsMenu (мод)        — строка в подменю шестерёнки, окно с заголовком = имя мода
 ├─ Tab                   — вкладка (необязательно: без вкладок окно одностраничное)
 │   ├─ Group             — группа с заголовком; .Collapsible() — сворачиваемая
 │   │   └─ настройки, текст, разделители, кнопки
 │   └─ настройки прямо во вкладке
 └─ настройки прямо в меню (если вкладок нет)
```

Добавлять элементы можно в любой контейнер (`SettingsMenu`, `Tab`, `Group`) одними и теми же методами.
Порядок на экране = порядок вызовов.

### 2.3 Виды настроек

| Метод | Значение `.Value` | Вид в окне | Подстройка |
|---|---|---|---|
| `Toggle(id, подпись, по умолч.)` | `bool` | ванильный флажок | — |
| `Number(id, подпись, по умолч.)` | `float` (+ `.IntValue`) | ползунок, поле ввода, кнопки −/+ в любой комбинации | `.Range(min, max)`, `.Step(s)`, `.Decimals(n)`, `.Unit("м/с")`, `.Slider()`, `.Field()`, `.Buttons()` |
| `Choice(id, подпись, ключ по умолч.)` | `string` — ключ варианта | выпадающий список, как ванильный combobox | `.Option(ключ, подпись)` |
| `Text(id, подпись, по умолч.)` | `string` | ванильное поле ввода | `.MaxLength(n)`, `.Placeholder(текст)` |
| `Color(id, подпись, по умолч.)` | `Color` | образец цвета; клик раскрывает HSV-ползунки и поле HEX | `.Alpha()` — с прозрачностью |
| `Hotkey(id, подпись, MyKeys [, MyKeyboardModifiers])` | `HotkeyValue` (клавиша + Ctrl/Shift/Alt) | строка как в ванильном «Управлении»: подпись слева, справа кнопка с клавишей («Ctrl + R»); щелчок — «нажмите клавишу» | `.EvenInMenus()`, `.CheckConflicts()`; очистить (Delete) можно всегда — не устраивает пустая, мод откажет в `Applying` |

Не настройки, а оформление и действия:

| Метод | Что делает |
|---|---|
| `Group(заголовок)` | группа; `.Collapsible(свёрнута = false)` |
| `Tab(заголовок)` | вкладка (только у `SettingsMenu`) |
| `Label(текст)` | пояснительный текст во всю ширину, переносится по словам |
| `Separator()` | линия-разделитель |
| `Button(подпись, Action)` | кнопка-действие; спросить игрока — `Menu.ShowConfirm` внутри действия |

**Числа.** Шаг применяется везде: ползунок ходит шагами, +/− прибавляют шаг, введённое в поле
округляется к шагу и зажимается в диапазон. Без `.Range` ползунка нет (не из чего строить), остаются поле и +/−.
Если элементы не указаны, вид по умолчанию: с диапазоном — ползунок + поле, без диапазона — поле + кнопки.

**Клавиши.** На действие — **одна** клавиша (с модификаторами). Можно выбрать любую клавишу клавиатуры
и любую кнопку мыши, в том числе левую и правую (в `MyKeys` они есть: `LeftButton`, `RightButton`, `MiddleButton`,
`ExtraButton1/2`) — как в ванильном «Управлении». Пока ждём клавишу, курсор спрятан; отмена — только Esc
(решение пользователя 2026-11-20: раньше щелчок левой/правой отменял ожидание, и их нельзя было назначить).
Проверка нажатия — у самой настройки, мод не разбирает модификаторы сам:

```csharp
LinkKey.IsPressed()       // держат сейчас (с нужными модификаторами)
LinkKey.IsNewPressed()    // нажали в этом кадре
LinkKey.IsNewReleased()
LinkKey.DisplayText       // "Ctrl + R" — для подсказок на HUD мода
```
`IsPressed/IsNewPressed` возвращают `false`, пока открыт чат или любое окно с курсором, чтобы клавиша
не срабатывала, когда игрок печатает текст. `.EvenInMenus()` отключает это для отдельной клавиши.

`.CheckConflicts()` — подсвечивать клавишу красным, если она занята (управление игры, другая клавиша мода,
клавиша другого мода центра). **По умолчанию проверки нет** (решение 2026-11-19): центр не знает, где клавиша
работает (R в игре — только с оружием в руках, у мода — например только с линкером), а конфликты с модами вне центра
(Ctrl у Build Vision) не видны вовсе. Сравнивается со всеми клавишами, в т.ч. без флага.

### 2.4 Общее у всех настроек

```csharp
T     Value { get; set; }     // текущее значение; set — мод задаёт значение (например, загруженное)
T     Default { get; }        // для кнопки «По умолчанию»
event Action<T> Changed;      // значение поменял игрок (после «ОК», который мод не отменил)
.Tooltip("текст")              // подсказка при наведении, как у ванили
.Enabled, .Visible            // у любого элемента (настройка, кнопка, группа, текст, разделитель); ставит мод, обычно в Menu.Editing
```

**Решение пользователя 2026-11-19 (вместо EnabledWhen / Button.Confirm):** центр не угадывает логику мода. Он передаёт моду
каждое изменение в окне сразу (`Menu.Editing`), нажатие кнопки, «ОК» и закрытие, а мод сам решает, что доступно, что видно и что
поменять. Значения до «ОК» живут в черновике окна (`.Value` меняется только после «ОК»).

```csharp
Menu.Opened  += () => ...;               // окно открыто (затем Editing с Changed = null)
Menu.Editing += e =>                     // игрок что-то поменял: галочка и список — сразу, ползунок — пока тянут, поле — когда ввод принят
{
    e.Changed                            // какая настройка (null — открытие окна или «По умолчанию»)
    e.New(Speed)                         // значение в окне (ещё не применено)
    Group.Enabled = e.New(Hints);        // доступность и видимость — у любого элемента
    Code.Visible  = e.New(Units) != "ms";
    e.Set(Scale, 2f);                    // поменять другое значение в окне (пресеты)
};
Menu.Closed  += ok => ...;               // окно закрыто: true — через «ОК» (после Applied), false — отмена, Esc, крестик
Menu.ShowMessage("текст" [, заголовок]);                 // окно с «ОК» поверх игры/окна
Menu.ShowConfirm("вопрос", yes => ... [, заголовок]);    // «Да» / «Нет», Esc = «Нет»
```

Присвоение `Value` из кода мода `Changed` не вызывает и ничего не сохраняет — это просто «вот текущее значение».
Если окно в этот момент открыто, оно покажет новое значение только для строк, которые игрок ещё не трогал.

### 2.5 «ОК»: проверка и отмена

На «ОК» центр передаёт моду новые значения. До того, как они станут `.Value`, вызывается `Menu.Applying`:

```csharp
Menu.Applying += e =>
{
    e.New(CruiseSpeed)        // новое значение (ещё не применено)
    e.IsChanged(CruiseSpeed)  // игрок его менял
    e.Cancel("Текст ошибки");             // отказать: окно остаётся открытым, значения в нём не теряются
    e.Cancel("Текст ошибки", CruiseSpeed); // + подсветить строку с ошибкой и прокрутить к ней
};
```

- Отказ → центр показывает сообщение об ошибке (как ванильное окно-сообщение, поверх окна настроек,
  кнопка «ОК»), игрок исправляет и жмёт «ОК» ещё раз.
- Без отказа → новые значения становятся `.Value`, у изменённых настроек срабатывает `Changed`,
  затем один раз `Menu.Applied` — удобное место, чтобы сохранить всё сразу.
- Простые границы проверять не нужно: `Number` сам держит значение в `.Range` и шаге, `Text` — в `.MaxLength`.

### 2.6 Своё окно

Если стандартного окна моду мало:

```csharp
// 1) Вместо стандартного окна — своё: клик по строке мода в подменю вызывает действие мода
Menu = new SettingsMenu("radar", "Radar Plus", "1.2");
Menu.CustomWindow(() => new RadarSettingsScreen().Open());   // свой MyModScreen
Menu.Register();

// 2) Стандартное окно + кнопка, открывающая своё окно для сложного
train.Button("Редактор маршрута…", () => new RouteEditor().Open());
```

Окно мода (`MyModScreen`) открывается поверх окна центра и прячет его, Esc возвращает назад —
так ведёт себя любой `MyModScreen` (проверено в W3 API Test).
**Позже (не v1):** центр отдаёт моду функции рисования ванильных контролов (кнопка, флажок, ползунок…),
чтобы своё окно выглядело так же без копирования кода.

### 2.7 Языки

**Перевода в центре нет** (решение пользователя 2026-11-20, отменяет `Menu.Translate`): мод сам решает, какие надписи
передавать в окно. Нужен другой язык — мод сам выбирает подписи по языку игры (`MyAPIGateway.Session.Config.Language`)
перед `Register()`. Тексты ошибок из `e.Cancel`, сообщения и `Info` — так же.
Свои надписи центра («ОК», «Отмена», «По умолчанию», «Нажмите клавишу…») — русский и английский по языку игры.

## 3. Окно настроек (то, что видит игрок)

```
┌──────────────────────── MagRail Systems ────────────────────────[×]┐
│   [ Linker ] [ Поезд ]                                             │
│ ───────────────────────────────────────────────────────────────── │
│  Скорость круиза        [−] ═════●════════════ [ 20 ] [+]  м/с    │
│  Единицы скорости       [ м/с                        ▼ ]          │
│  ▼ HUD                                                            │
│     Подсказки на экране                                   [✓]     │
│     Масштаб              ════●═══════════════ [ 1.0 ]             │
│     Цвет подсветки рельса                                 [■■]    │
│ ───────────────────────────────────────────────────────────────── │
│  [ Сбросить статистику поездов ]                                ▐ │
│                                                                    │
│  [ По умолчанию ]                         [ Отмена ]  [   ОК   ]  │
└────────────────────────────────────────────────────────────────────┘
```

- Всё ванильное: панель `MyModScreen` с затемнением фона, крестик, заголовок `ScreenCaption` 0.8,
  вкладки — текстуры кнопок (активная = `button_default_active`), подписи `Blue` 0.8, подсказки 0.7,
  флажок, ползунок, поле ввода (`textbox_*`), combobox (`combobox_default_*`), кнопки −/+
  (`button_decrease/increase*`), ползунок оттенка (`hue_slider_*`), полоса прокрутки. Все эти текстуры
  есть в `Content\Textures\GUI\Controls`. Стиль — `~/.claude/notes/se-vanilla-gui-style.md`.
- Две колонки: подпись слева, контрол справа. Если строк больше, чем помещается, — прокрутка колесом и полосой.
- **ОК / Отмена**, как в ванильных «Параметрах»: до «ОК» моду ничего не уходит, «Отмена», Esc и крестик
  всё откатывают. «ОК» — см. 2.5 (мод может отказать).
- **«По умолчанию»** — общая кнопка внизу, ставит значения по умолчанию (`Default`, их задаёт мод)
  **во всём моде**, на всех вкладках. Это ещё не принято — нужен «ОК».
- Назначение клавиши: клик по кнопке клавиши → поверх окна надпись «Нажмите клавишу… (Esc — отмена,
  Delete — очистить)». Рисуется внутри окна центра, а не отдельным `MyModScreen` (лимит 4 окна модов).
- Конфликт клавиш: если та же комбинация занята в другом моде центра или в управлении игры
  (`IMyInput.GetControl(MyKeys, MyKeyboardModifiers)`), название клавиши красное, в подсказке сказано,
  где она занята. Сохранить можно. Только у клавиш с `.CheckConflicts()` (по умолчанию выключено).
- Кнопка-шестерёнка и подменю — как решено раньше (заметка, раздел «Решения пользователя»).

## 4. Значения и хранение

Центр значения **не хранит**. Мод:
1. при загрузке задаёт `.Value` (из своего хранилища; если ничего не сохранено — остаётся `Default`);
2. сохраняет в `Menu.Applied` (или в `Changed` отдельных настроек).

Где и как хранить — дело мода (локальное хранилище, мир, свой формат).
Окно при открытии берёт текущие `.Value`, поэтому всегда показывает то, что действует в моде.

---

## 5. Порядок загрузки и «нет центра»

- `SendModMessage` вызывает обработчики сразу, поэтому порядок модов не важен: если центр загрузился
  раньше, он принимает `Register()` сразу; если позже — сам рассылает «я готов», и клиенты
  регистрируются повторно.
- Значения живут в клиентском файле мода, поэтому `.Value`, `IsPressed()` и т.п. работают и без центра.
- Если центра нет (мод запущен локально без зависимости или центр сломан), у мода просто нет окна
  настроек: `Menu.IsConnected = false`, в лог одна строка.

---

## 6. Протокол (для нас, мододел не видит)

- Канал — фиксированный `long`. Регистрация несёт **номер версии протокола**: центр понимает старые
  версии клиента, клиент новее центра получает отказ и пишет в лог.
- Между модами можно передавать только типы игры и .NET (свои классы у каждого мода — разные типы),
  поэтому описание меню уходит деревом из `object[]` / `Dictionary<string, object>`, значения — строками
  (инвариантная культура), а связь обратно — делегатами: «дай текущие значения» (при открытии окна),
  «вот новые значения — принимаешь?» (на «ОК», ответ — `null` или текст ошибки + id строки),
  `Action` для кнопок и своего окна. Так же работают Build Vision API и Rich HUD.

## 7. Этапы

1. **Пробой** (маленький мод): шестерёнка в меню Esc; рисование и мышь в меню Esc на паузе;
   делегаты через `SendModMessage` между двумя модами и порядок загрузки;
   `IsKeyPress` для кнопок мыши через `MyKeys`.
2. **Ядро центра:** регистрация, подменю, окно с флажком и числом, ОК/Отмена/По умолчанию, отказ мода.
3. **Все контролы**, вкладки, группы, подсказки, конфликты клавиш (языки — делом мода, см. 2.7).
4. **Тестовый мод** `Mods\Mod settings Test` — все контролы, значения на экран, отказ на «ОК».
5. **MagRail** — первый настоящий клиент (переназначение R и Ctrl у Linker).
6. Публикация: инструмент `F:\Games\SEWorkshopUpload` учится ставить обязательную зависимость; README для мододелов.

### 4.1 Помощник сохранения (решено 2026-11-19)

В `ModSettings.cs` есть необязательные `Menu.SaveToLocalStorage()` / `Menu.LoadFromLocalStorage()`:
все значения меню — в один файл в локальном хранилище **самого мода** (не центра). Типичный мод:

```csharp
Menu.LoadFromLocalStorage();                    // после описания настроек, до Register()
Menu.Applied += () => Menu.SaveToLocalStorage();
```
Мод, которому нужно своё хранение, их не вызывает.
